# Player guide

Document L03 · Dossier 2.5.0-g2 · 26 September 2026. Application 2.5.0; model V2-2.3.0. Audience: players. Language: British English. Intended destination: public documentation. Formats: Markdown, PDF and DOCX. Author: G2 teaching/manuals specialist; independent review is recorded in the dossier inventory.

## Your role

You are part of a campus Task Force responding to heat-related climate pressure. Over three decision turns, you choose interventions, encounter events and adapt. The aim is to understand the consequences of your choices across the whole trajectory. The game does not prescribe an optimal package.

Open the candidate supplied for your session. On the home screen, **How it works** opens the orientation; **Begin a new game** starts the entry flow. A first run may open the orientation automatically. Complete each practice activity to enable its next step, or use **Skip orientation**. Select a campus, enter the Task Force briefing and read its conditions and mission before choosing **Join the Task Force**. The four campuses share a catalogue but face different constraints.

## Read the indicators

| Indicator | How to read it |
|---|---|
| Risk | A synthetic exposure/outcome index; lower is better. It is not a percentage probability. |
| Resilience | A synthetic capacity index; higher is better. |
| Continuity | A synthetic index of maintaining campus services; higher is better. |
| Acceptability | A synthetic index of how the response is received; higher is better. |
| Budget | Relative resources available for game decisions; not money or a score to maximise. |
| Coordination pressure | The delivery demands of this turn's planned work, shown with a band and expected implementation. |

Resources arrive in stages. Unused resources carry forward, and events may adjust them. Read the current available amount rather than treating the total programme budget as immediately spendable. After commitment the display distinguishes spent resources, carried resources and event adjustments. At the end of turn 3, remaining resources are end-of-run resources, not a fourth-turn allowance.

## Build a planning portfolio

The catalogue contains 36 interventions across Infrastructure, Operations, Preparedness, Governance, Behavioural and Restrictive categories. Search by name or description, or filter by category, lifecycle state, capability tag and delivery timing. **Selected only** shows the current planned actions. **Clear filters** restores the full view.

Open a card to read purpose, timing, benefit and trade-off. The closed card also distinguishes **Current** state from **Planned** action and cost. A planned action has not yet been implemented. Select an available action:

- **Start L1** or **Start L2** begins an intervention at the chosen level.
- **Upgrade** raises an eligible active L1 intervention to L2.
- **Repair** is offered for an eligible damaged intervention.

Unavailable choices include an explanation, for example insufficient resources, an unsuitable state or a delivery path that cannot produce a benefit before the final evaluation. Starting at L2 and starting at L1 before a later upgrade are different commitments in time. Do not assume that their timing is interchangeable.

Started interventions persist through the run. They do not require renewal, recurring maintenance payments or an expiry countdown. Activation and maturity still take time, and events can damage eligible interventions. A damaged intervention may require repair to restore its contribution. Read the state shown on its card.

The portfolio panel lists selected actions, their total cost and remaining resources. Remove an action with its remove control to revise the plan. Coordination depends on the work involved, the categories opened and the relationships among choices. There is no rule that automatically penalises the fourth action merely because it is fourth; use the displayed pressure assessment. An empty commitment is also a valid game choice.

## Use the campus map

The map helps you locate interventions and inspect state. It is a schematic illustration, not a geographic measurement or a quantitative forecast. Select a marker or cluster for details. During planning, **Open intervention details** opens the corresponding catalogue card, including when filters had hidden it.

Use the map's pan, zoom and fit controls; dragging or pinching is not required. A text alternative provides campus information. The catalogue and text remain important: colour, animation and music are not the only carriers of gameplay information.

## Commit, then face the event

Choose **Review commitment**. Inspect cost, operations and coordination pressure. You can remove selections or use **Edit portfolio** to return. Choose **Commit & reveal event** only when ready: after the event is revealed, this turn's decision cannot be edited.

There is an intermediate event after each of the first two turns and a final stress event after the third. When the event presents response options, select one and choose **Confirm response**. The interface then explains what happened, what protected the campus, pressures that increased impact, any damage and effects continuing beyond the current turn.

Distinguish the event's **Before event / After event** comparison from **Whole-turn outcome**. The whole-turn view also includes your decisions, active effects and interactions. A change in the whole-turn total must not be attributed entirely to the event. Effects described beyond the final horizon may be contextual information rather than an additional scored turn.

Continue to the next turn and read **Since the last turn** before planning again. This recap helps connect the last event, damage and carried effects to your next decision. After the third event, choose **Open the debrief**.

## Read the debrief

The debrief combines the campus trajectory, Task Force reflections, strengths, compromises and reflection questions. Its six component labels are **Risk reduction performance**, **Resilience growth**, **Service continuity**, **Acceptability**, **Portfolio coherence** and **Resource efficiency**. Mission review is shown separately from the composite score.

The displayed score bands are Strong (85–100), Passed (70–84), Needs consolidation (50–69) and Redesign (below 50). They describe the model result. They do not measure learning, individual ability or the safety of a real campus. Read the evidence for your choices before deciding what to change.

**Replay the same conditions** keeps the scenario and recorded seed. With the same choices and build, results are reproducible. Different decisions can change outcomes; a seed alone is not a promise of identical consequences. **Replay with new events** keeps the scenario and generates a new seed. **Choose another campus** returns to scenario selection. Export any record you want to retain before replacing current progress.

## Save, resume and exchange a run

The current run is saved locally in the browser. Use **Save & exit** to pause. If asked whether to leave a planning draft, **Save and leave** preserves selections and catalogue view, **Discard draft** leaves without that draft, and **Keep planning** stays on the current screen. Use **Continue your run** from home to resume.

Browser profile and game address matter. Another browser, private browsing session, device or hosting address does not automatically see these saves. Clearing site data can remove runs and preferences. Follow any storage warning: when temporary storage is in use, do not assume progress will survive closing the session.

In **Advanced settings**, **Export JSON** and **Export XLSX** download the current run. The XLSX file is a run-exchange container, not the dossier's payoff workbook. The separate uncommitted planning draft is not included in the run export; preserve it locally or record its choices separately. Keep an untouched export for later import. If you analyse a copy, do not overwrite the exchange original.

Use **Import** to choose a compatible exported file. Save or export the current run first, since a successful import replaces the active run. An incompatible or invalid import is rejected; a reported failed import leaves the current run unchanged. The 2.5.0 contract requires matching build fingerprints. A shared version number alone does not guarantee compatibility. Earlier versions are archive-only and are not migrated into the current run.

Completed current-version runs can be compared in **Advanced settings → Compare completed runs**. Select two runs from the same campus and choose **Compare**. The table reports whether events match and shows changes as second run minus first. This comparison is descriptive; it does not alter either record or prove that one action alone caused a difference.

## Comfort, access and recovery

**Experience settings** provides sound, volume, motion and sensory-intensity controls. The game can be played with sound off. If sound pauses, use the displayed sound/resume control when ready. A failure to play audio does not remove gameplay information.

Keyboard users can move among controls with Tab and Shift+Tab and activate buttons with the usual keyboard controls. Read the named text controls and map alternative if the illustrated view is less useful. Automated accessibility checks are documented, but a full human assistive-technology evaluation is not claimed.

If the catalogue seems empty, clear filters. If an action is unavailable, read the reason beside it. If a save or commitment fails, keep the page open and read the notice; use its retry option only after checking the stated issue. Export the current run where possible. Avoid starting a replacement run as a recovery step before protecting the existing record.
