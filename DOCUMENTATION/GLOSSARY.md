# Dossier terminology

Application 2.5.0; model V2-2.3.0; documentation revision 1, 26 September 2026. Audience: all dossier readers. Language: English. Public reference. Author: editorial coordinator; independent review recorded in the inventory.

| Term | Meaning in this dossier |
|---|---|
| Application version | The interface, persistence and distribution identity; currently 2.5.0. |
| Model version | The retained parameter and model-data identity V2-2.3.0. It differs from the application version and the rule revision. |
| Rule revision | The algorithm identity; current coordination-v2 corrects pair lookup. Its exact fingerprint distinguishes it from earlier 2.5.0 candidates with the same model values. |
| Turn | One decision period representing an academic year centred on its hot season; three turns form a run. |
| Risk | A synthetic index for which lower is better, not an event probability. |
| Resilience | A synthetic capacity index for which higher is better. |
| Continuity | A synthetic index of maintaining campus services. |
| Acceptability | A synthetic index of social acceptance of the response. |
| Budget | Relative game resources, not currency. Scheduled release, available resources and carryover are distinct. |
| Planning draft | Local uncommitted selections and catalogue view; separate from a run export. |
| Operation | Start L1, Start L2, Upgrade or contextual Repair on an intervention. |
| Coordination load | Turn-local delivery work, category heterogeneity and bounded complementarity relative to capacity. |
| Maturity | Timing of physical benefits or capability contribution; those curves can differ. |
| Capability | The model's tag-based contribution used by event response and coordination mechanisms. |
| Event-only change | The realised change caused by the event stage, excluding preceding portfolio effects. |
| Whole-turn change | The recorded change across the entire committed turn, including portfolio effects. |
| Active score | The score displayed by the game; distinct from unadopted shadow research methods. |
| Audit workbook | Current parameter tables and expressly selected formula checks; not a full engine or a run-import file. |
| Same-build compatibility | Matching declared schemas and fingerprints, not merely the same version label. |
| Historical source | Preserved evidence of an earlier document/model, not current operational authority. |
| Technical qualification | The specific automated checks and exact files identified by G1, with its stated limitations. |

Terminology follows the current canonical model, qualified interface and G1 handoff. Exact source locators are held in the private G2 traceability map.
